ghostrefs находит символы, единственными известными потребителями которых являются тесты,
включая транзитивные цепочки `test → helper → target`.

Поддерживается Python через `pyright-langserver`, который должен быть в `PATH`.
Пути `--source` и `--tests` разрешаются относительно `--root`. Корень должен
соответствовать импортам проекта: для примера ниже это корень репозитория.

```sh
cargo run -- --root . --source fixtures/python/project --tests fixtures/python/tests
```

Пример на fixtures:

```text
TestOnly …/main.py:6:5 test_only_used_func (Function)
TestOnly …/main.py:14:7 TestOnlyUsedClass (Class)
TestOnly candidates: 2 (6 production symbols analyzed)
```

Сканер находит Python-файлы во всём `--root`, пропуская `.git`, `.venv`, `venv`,
`__pycache__` и символьные ссылки на директории. Файлы вне source/tests тоже
открываются в LSP, чтобы не пропускать внешних потребителей внутри workspace.
Если source/tests находятся за пределами root, они сканируются дополнительно.
LSP возвращает объявления через
`textDocument/documentSymbol`, затем использования каждого символа через
`textDocument/references`. Полные имена (`Class.method`, `outer.inner`)
сохраняются из вложенности ответа LSP. Ошибки запросов прерывают анализ;
неполный ответ не подменяется успешным результатом.

Граф направлен от потребителя к используемому символу. Владелец ссылки — самое
вложенное объявление функции, метода или класса, содержащее её позицию.
Ссылки вне объявлений, включая импорты на уровне файла, принадлежат модулю.
Ссылки в декораторах принадлежат внешней области: декораторы выполняются при
определении функции или класса. LSP-диапазон объявления включает декораторы,
поэтому позиции перед именем объявления исключаются из его области.
Для несобранных документов владелец остаётся неизвестным. Ссылки на класс
консервативно активируют его непосредственные члены: это учитывает конструкторы,
дескрипторы и методы без явной ссылки на них. Обычные рёбра сохраняют позицию
ссылки, рёбра активации членов класса отмечаются отдельно.

Production-корнями считаются все production-модули, верхнеуровневые функции
`main` и верхнеуровневые объявления без известных потребителей, кроме самих себя.
Последнее правило консервативно сохраняет зависимости потенциальных внешних
точек входа. Внутренний формат точки входа — `EntryPoint { path, qualname }`:
канонический абсолютный путь и полное имя. Выбор корней выполняется внутри
анализа; дополнительные production-точки входа задаются в проектном JSON,
без дополнительных параметров CLI.

Тестовые модули и объявления служат корнями тестового обхода. Внешние ссылки
и символы с неопределённым результатом LSP запускают отдельные обходы. Циклы
обрабатываются через набор посещённых узлов. Анализ присваивает production-объявлениям статусы:

- `TestOnly` — достижимы из тестов, но не из production, внешних или неизвестных корней.
- `UsedInProduction` — достижимы из production-корней.
- `UsedOutsideScope` — достижимы из внешних корней, но не из production.
- `Unknown` — LSP вернул `null` для ссылок символа, либо символ достижим из
  неизвестного корня и не имеет известной production- или внешней достижимости.
  Явно заданная production-точка входа считается production-достижимой даже
  при неопределённом ответе на запрос её потребителей.
- `Unreferenced` — нет потребителей, кроме возможных ссылок на самого себя;
  зависимости такого верхнеуровневого объявления всё равно учитываются как production.
- `Unreachable` — есть потребители, но нет достижимости ни из одного набора корней,
  например замкнутый цикл без входящих ссылок.

В отчёт попадают только кандидаты `TestOnly` и итоговый счётчик. Тестовые
объявления, локальные переменные и параметры исключаются из отчёта.
Верхнеуровневые переменные могут быть кандидатами. Сами данные сохраняются
в графе. `main` считается production-точкой входа даже без ссылок на неё.

Для объяснений добавьте `--verbose`: будут показаны production-корни,
неизвестные корни, ссылки и цепочки от тестов до находок. Для вывода рёбер вместо отчёта используйте
`--graph`. Настройки Pyright находятся в `ghostrefs-lsp.json`.

Проектные настройки читаются при каждом запуске из `ghostrefs-lsp.json` в
`--root` и дополняют встроенные настройки. Объекты объединяются рекурсивно,
массивы заменяются целиком. Без проектного файла используются встроенные настройки.
Для исключения областей с внешними потребителями задайте `ghostrefs.ignore`:

```json
{
  "ghostrefs": {
    "ignore": ["**/templatetags/**"]
  }
}
```

Шаблоны сопоставляются с путями файлов относительно `--root`: `*` и `?` работают
в пределах одной директории, `**` — через произвольное число директорий.
Допустимы и точные пути, например `server/wsgi.py`. По умолчанию список пуст;
в анализаторе нет встроенных исключений для Django или других фреймворков.
Некорректные настройки и glob-шаблоны приводят к ошибке перед запуском LSP.

Игнорируемые файлы продолжают собираться и остаются в графе. Их символы
исключаются из отчёта, а их узлы становятся неизвестными корнями. Поэтому
зависимости таких файлов, в том числе транзитивные в других директориях,
не объявляются `TestOnly`. Блок `ghostrefs` обрабатывается самим анализатором
и не передаётся серверу; остальные настройки передаются LSP.

Для функций, запускаемых через внешнюю конфигурацию, задайте
`ghostrefs.production_entrypoints`:

```json
{
  "ghostrefs": {
    "production_entrypoints": [
      {
        "path": "server/apps/scoring/workflows/scoring_pipeline.py",
        "qualname": "scoring_pipeline"
      }
    ]
  }
}
```

`path` — путь существующего файла относительно `--root`, `qualname` — полное
имя символа, например `scoring_pipeline`, `Service.execute` или `outer.inner`.
Эти узлы дополняют автоматически найденные production-корни. Все достижимые
из них зависимости учитываются как production, включая транзитивные цепочки.
Остальные символы того же файла продолжают анализироваться обычным образом.
Файл должен находиться в `--source` за пределами `--tests` и не попадать под
`ignore`. Несуществующее или неоднозначное имя символа приводит к ошибке анализа.

Это анализ известных LSP связей с консервативными правилами достижимости.
Импорт считается использованием, даже если импортированное имя далее не читается;
production-импорт может поэтому скрыть кандидата. Все production-модули считаются
потенциально исполняемыми. Значения аргументов по умолчанию могут
попадать в область функции, хотя вычисляются при её определении. Динамические
импорты, рефлексия, плагины и внешние потребители пакета не восстанавливаются
полностью. Ошибки разрешения импортов в Pyright могут приводить к пропущенным
связям, поэтому `TestOnly` — кандидат для проверки, а не доказательство безопасного
удаления кода. Требуется поддержка вложенных объявлений со стороны LSP-сервера.

Сам по себе декоратор не делает объявление точкой входа и не исключает его из
`TestOnly`. Конфигурации внешнего запуска (например, `prefect.yaml`) автоматически
не читаются: их точки входа можно указать в `production_entrypoints`.
